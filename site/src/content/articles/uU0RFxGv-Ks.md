## セクション

### フルナンバーアップグレード — Sonnet 5 の性能面の衝撃

- 時刻: 00:22

Alex Finn はまず Sonnet 5 が『4.8→4.9』のようなマイナー更新ではなく、フルナンバーの上位モデルであることを強調する。旧世代の Opus 4.6 を、より軽量・安価・高速なこの新型モデルが上回った点が象徴的だ。Claude はエージェント系モデルで長らく首位を維持してきたが、OpenClaw や Hermes を使うユーザーは Claude 系モデルを使う際に API 料金がかさむことに不満を抱いていた。

Sonnet 5 の登場でこの構図が変わる。Opus 4.8 にほぼ匹敵する性能を、大幅に安い価格で使えるようになったためだ。動画の前半はこの性能変化を数値とともに具体的に示す構成になっている。

### 実機比較テスト — 視覚生成でも旧モデルを上回る

- 時刻: 05:14

実演では海の嵐のシーンをシミュレーションし、Sonnet 5 と Sonnet 5.5 の出力を比較する。波の動き、船の揺れ、雷の表現において Sonnet 5 のほうが自然で説得力のある結果を出したと Alex は評価する。風を強めると波が船に打ち付ける様子が生成され、視覚的なクオリティの底上げが確認できる。

一方で価格面の留保も忘れない。この結果は Sonnet 5 のほうが良いと感じたものの、ChatGPT のほうが価格面では依然優位な場面が多い。特に API 課金でコーディング作業をこなす用途では ChatGPT 側に分があると Alex は付け加える。UI の使いやすさでは Claude 系が勝るとしつつも、価格重視のユーザーには ChatGPT を勧める場面が残る、というバランスの取れた評価だ。

### 推奨の使い分け戦略 — Sonnet はコーディング、Opus は計画立案

Alex が提示する実践的な使い分けは明快だ。基本的なコーディングタスクには Sonnet を、計画立案や本当に複雑なタスクには Opus 4.8 の ultra モードを充てる。Claude Code Desktop での作業フローとして具体的に示される。

終盤では Fable 5 の復活予告にも触れる。米国内限定で本人確認(ID verification)が必須になる見込みで、米国外のユーザーは利用できない可能性がある。Alex 自身は『違法なことは何もしていないので確認には応じる』としつつ、API 課金と ID 確認という2つのハードルを冷静に受け止める。結論として Sonnet 5 は Opus 4.8 の完全な代替ではなく、OpenClaw や Hermes のように月額コストがかさむ場面でのコスト削減という、戦略的に限定された領域での置き換えとして位置づけている。

## 編集部の視点

Alex Finn の評価が実用的なのは、Sonnet 5 を『Opus の代替』ではなく『特定領域での戦略的な置き換え』と明確に線引きしている点だ。この線引きの感覚こそが、複数モデルが乱立する現在の AI 環境で最も価値のあるスキルになっている。読者にとっての含意は二つある。第一に、コスト最適化はモデル単体の性能比較ではなく、タスクの種類ごとに『どのモデルへルーティングするか』の設計問題として捉えるべきだ。第二に、Fable 5 の米国限定 ID 確認方針が示すように、AI 企業のガバナンス方針は地域ごとのアクセス格差を生み始めている。グローバルに AI ツールを組み合わせて使う開発者にとって、モデル選定は性能だけでなく利用条件の地理的制約も含めて評価すべき局面に入っている。
